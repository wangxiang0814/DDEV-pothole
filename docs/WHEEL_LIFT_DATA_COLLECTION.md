# 左右单轮迹抬轮与仿真数据采集方案

## 场景参数

场景 JSON 用整数厘米保存 `length_cm`（50–100）、`width_cm`（50–100）、`depth_cm`（10–40）和 `offset_cm`。纵向近沿位置用整数米 10–15，车辆在 `s=0` 起步。`side` 为 `left` 或 `right`，正横移表示往目标轮迹外侧移。建议偏移上限为 `min(20, floor(width_cm/2)−20)` 厘米。坑轴平行于道路，附着固定 0.70。米制几何由同一份整数配置生成。上述范围属于探索范围，训练批次以原生验证通过的子域为准。

1.925 m 轴距为纵向几何上限。前轮落轮时还应满足前轮越过远沿至少 0.30 m、后轮停在近沿前至少 0.05 m，并检查实测车速和轮位。40 cm 深度超过轮胎半径，属于外边界诊断。只要坑底不发生接触，增加深度也未必增加动力学响应的多样性。

边界验证优先覆盖 50/100 cm 长、50/100 cm 宽、10/40 cm 深、正负极限横移及 10/15 m 起点。先成对验证 80×90×20 cm 名义点，再测组合角点。量产 LHS 在已验证的子域内做五维分层。连续坐标映射到整数档后检查重复与分层覆盖，按几何组分割数据，左右镜像和重复轮次随组划分。

左侧镜像入口能执行直行和坑前停车。固定载荷造成横向不对称，名义左侧纯镜像在参考时间 7 s 停滞，按实测静载对齐后推进到 22.04 s，目标轮最低滤波载荷仍约 1.57 kN，卸载期间最大重心三角形系数约 −0.063。左侧需要按实测左右响应重新设计预载和重心转移，通过原有验收后再进入随机采集。右侧通过结论仅覆盖表中的离散点。

复现实例为 `python scripts/run_strategy.py --strategy wheel_lift --case seed_repeat --lift-scene scene.json --approach-distance-m 12 --run-id UNIQUE`。场景文件可用 `{"side":"left","length_cm":80,"width_cm":90,"depth_cm":20,"offset_cm":0}`。仿真使用隔离模型，现有增益来源先经原模型校验，之后才生成新几何。

## 镜像复核（2026-11-13）

撤回此前仅左侧启用的静载校正。给定相同的规范坐标观测，两侧状态机、卸载参考和执行器命令相同；外层交换左右车轮通道，按轴系变换横向坐标及横摆、侧倾和转向符号。原验收不变。响应型单轮迹场景对 80–100 cm 的坑长，从 0.50 m 线性增加前轮制动提前量至 0.60 m，从 2.50 s 线性缩短后轮加速斜坡至 2.10 s，并将前轮阶段支撑反馈限幅由 500 N 线性增至 550 N。两组 100×100 cm 右侧长坑（深 10/40 cm、起始距坑 10/15 m）用相同参数在原偏载车型上通过；此结论不适用于居中配载。

源车型有两件横向对称的 200 kg 载荷，以及一件横向左偏 0.50 m 的 200 kg 载荷。同一名义坑对照，停车后实测车身重心偏左约 8.7 cm；移除目标前轮后的最小重心三角形系数，右侧约 +0.067、左侧约 −0.063，抬升准入要求 +0.05。原车的局部辨识即使不要求左前轮卸载，给出的最优线性估计仍约 −0.0038；四组原生有界力试验中，最佳有效实测裕度约 −0.0063，彼时左前轮轮载约 3.17 kN。反转载荷仅用于隔离诊断：它让左侧达到抬升入口，随后在悬空转换分配中失败，不能算通过。这些数据支持当前固定车辆和现有悬架策略的限制，不证明任意非线性控制都不可行。

居中开发版 `tuned_ii_centered_payload_20261113` 只修改生成副本中第三件载荷的横向位置（500 mm→0）和显示偏移（0.5 m→0）；三件载荷质量与原车型均保持不变。用 `python scripts/run_strategy.py --strategy wheel_lift --case seed_repeat --manifest configs/wheel_lift/centered_payload_development.json --lift-scene scene.json --run-id UNIQUE` 复现。该清单禁用旧的支撑 QP 增益，禁止数据采集，结果记录车型及模型哈希。

居中开发版名义右侧在旧参考下卸载超时，原生停车实测车身重心距中心线约 1 mm。右前轮有界力试验中曾稳定降至约 56–76 N，三个支撑轮均超过 500 N，但轮载估计的 ZMP 三角形裕度约 0.036–0.038，低于 0.05，不能进入过坑。近卸载点的四角正负力辨识尚未给出满足现有姿态、轮载和裕度的局部修正；正式左右边界验收未开始。

## 每轮保存内容

| 文件 | 内容 |
|---|---|
| `model/run_all.par`、`simfile.sim`、`scenario.json`、`visual_assets/` | 实际求解输入、场景参数及原生显示资源 |
| `model/output/*.vs`、`*.vsb`、`*_all.par` | 原生可回放历史，验收与边界轮次保留 |
| `native_5ms.csv` | 现有原生动作和响应诊断。保持真实物理轮位，原生单位。 |
| `*_control_20ms.csv`、`*_observed_20ms.csv` | 反馈、控制器、相位、稳定裕度和故障诊断。左侧当前内部日志采用右侧规范坐标。 |
| `state_20ms.csv` | 规划文件。按 `step,time_s` 存储 SI 真实状态、动作扩充所需关键响应和结构化坑槽感知。 |
| `action_20ms.csv` | 规划文件。`step,t0_s,t1_s` 与状态行对齐，保存九路起始指令和区间均值，显式扰动另列。 |
| `channels.json`、`run_manifest.json`、`result.json`、`run.log` | 字段名、单位、轴系、轮序、采样语义、源码/模型哈希、验收与求解日志。批次另存清单及逐轮状态。 |

扩充状态至少保留每轮纵/横/垂向胎力 `Fx/Fy/Fz`、回正力矩 `Mz`、滑移率、侧偏角、有效半径、接触压缩、轮心及接触点坐标、地面高度。悬架保留 `Jnc/JncR`、弹簧力 `Fs`、阻尼器力 `Fd`、外加弹簧力 `FsExt`、压缩/回弹限位信号。车身保留原点位置、姿态、车身加速度、角速度、重心和支撑点；控制诊断保留支撑裕度、QP 状态、饱和、阶段和异常。`IMP_FS` 是实际送给求解器的指令，`FsExt` 是求解器记录的外加弹簧力，两者独立存储。

原生轮侧符号与单位写入字段字典。`Vx_SM/Vy_SM/Vz_SM`、`Zcg_SM`、`Steer_L1/Steer_R1/Steer_SW` 在本机 TruckSim 输出表中可查，正式采集前需将其追加到采集专用导出端口并试跑核对。50 Hz 记录用积分步边界的因果对齐，不能从当前 5 ms CSV 直接把相邻时刻的状态和动作当作精确同步标签。

## 结构化坑槽感知

保存坑的世界坐标中心、近沿/远沿和四个顶点，以及每个采样时刻的自车坐标。用同帧车身原点 `Xo/Yo`、航向 `Yaw` 将坑中心和顶点旋转到自车平面坐标系。逐帧保存坑中心纵横距离 `dx/dy`、直线距离、相对方位 `atan2(dy,dx)`、坑轴相对航向、近远沿的纵向距离。沿坑运动期间更新这些量。记录 `scene_truth` 来源，模型的感知输入只能使用推理时可获得的同帧特征。目标侧别、轮序、符号、几何尺寸与原始世界坐标均存元数据。

## 样本验收

以仿真时间 0.02 s 为间隔核对单调、无缺帧、有限值与单位。两侧的真实轮载、轮位、抬升与落轮事件应与阶段一致。至少保存一组左右成对的可回放验收轮次，以及失败边界的诊断文件。模仿数据仅使用原生验收通过的轨迹，动力学失败片段另行标注。正式采集前对同一工况做开启/关闭采集对照，核对控制动作与求解结果。
