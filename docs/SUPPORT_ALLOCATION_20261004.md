# FR/RR 在线支撑分配：2026-10-04

## 本轮范围

在已验证的 compact3、横向表 scale=0、RR robust、FR 转向反馈版本上，新增可选 `SupportAllocationFeedback`。固定车型、质量、载荷位置、标称坑槽和 μ=0.7，不重建 TruckSim、不引入 RL、完整 WBC 或 MPC。原生积分步长 0.5 ms，控制/QP 20 ms；验收依据无噪声 plant truth。

新增模块仅介入 FR/RR 三轮保持、蠕行、停车。卸载、离地转换及速度/方向控制保留已有闭环。落轮时将附加修正按 4 s 五次曲线释放；RR 中止冻结的实际悬架力已经包含修正，外层不得再加一次。

## 算法

1. 轻度低通轮载，根据真实轮接地点计算准静态轮载 ZMP、支撑三角形及 CoM 裕度。
2. 取当前稳定点到 λ≥0.075 收缩三角形的最近点。上层轮载 QP 满足总轮载及两个力矩等式、支撑轮≥500 N、抬起轮目标零载，不追求均载。
3. 下层优化三个支撑悬架的力增量，抬起轮输入作为已知量计入局部模型耦合。使用分别辨识的 FR/RR 轮载、姿态、CoM、ZMP、行程和轮心高度增益，软目标为轮载/姿态跟踪及输入正则，姿态参考加入角速度阻尼。
4. 预测硬约束：两种稳定点 λ≥0.05、支撑轮≥500 N、抬起轮≤100 N、抬起轮相对平地顶面的净空≥10 mm、各角行程、姿态、总输入及附加修正限幅。每步附加修正变化≤8 N，累计≤500 N。实际非线性状态仍由原有阶段判据验收，局部预测不替代真实测量。
5. 持续分配失败≥0.5 s 进入既有停车/恢复流程，记录初始原因。下层并不强迫动态实际轮载总和恒定；上层总载荷等式是准静态目标。

全部新参数集中在 `config.py / SUPPORT_QP`。当前姿态权重 2、局部跟踪增益 0.1、角速度阻尼 0.8 s；FR/RR 实际姿态限仍分别沿用 8°/10°，没有新增静稳角速度门槛到运动阶段。

## 辨识与适用性

`support_allocation_gains_20261003.json` 保留已发布三模式增益，并从同一批经过模型哈希核验的 ±250 N 原生探针 CSV 的稳态窗口补充轮心高度中心差分。原 `current_contact_gains_20261003.json` 不覆盖、不改写。后续辨识入口也自动输出高度增益。

源模型 `run_all.par` SHA256：`85ff4e994a6fb98e7f819d0c5ffdfe43b2b4870c31942d1915b68cddc00f70d2`。启动前严格校验模型哈希及六类有限矩阵的维度；改变附着、起点、运动学或其他车型参数需要对应辨识，不能直接将此增益伪装成新车型增益。高度基于平地顶面 z=0，尚不适用于起伏地面。

模型为保持姿态附近的准静态局部响应，有效秩不足；使用正则化优化，不用普通增益逆矩阵。单步虽小，但累计修正与运动过程可能超出辨识有效范围，必须继续用非线性试验核验。

首次 FAIL 原因：将稳态增益作为快速累积反馈，车身姿态滞后，RR 临近停车时横滚超过 10°，触发中止。RR 尚未完全越过固地恢复线，未安全完成恢复，不能标为可控恢复成功。后续降低跟踪增益、用原始角度做硬预测并加角速度软阻尼，再提高姿态目标权重，实际重跑得到上述 PASS。

当前两轮分配均无不可行；本机求解 p95 为 3.06/3.93 ms，第一轮最大 5.40 ms。包括上下层求解时间，不包含全仿真和其他控制工作，不保证硬实时。初始 shadow 试验早于高度模型/约束补充，仅用于证明旧动作未改变，不能当作高度约束验证。

坑前 `RR_HOLD` 注入中止时，附加修正 FL/FR/RL 为约 -30.72/+25.22/+0.49 N。实际力快照交接跳变 0 N，外层修正清零但快照保留实际力，再平滑落轮。恢复 PASS，正常过坑任务 FAIL；恢复过程中单个 20 ms 记录间最大力变化 20.64 N。坑上和支撑丢失恢复未覆盖。

## 复现

```powershell
$env:PYTHONPATH='src'
python scripts/run_right_side_full_cycle.py --output runs/qp_recheck --efficiency-profile compact --lateral-ride-scale 0 --rear-control-profile robust --front-steering-feedback --front-target-speed-kph 3.4 --front-min-pit-speed-kph 3 --front-brake-lead-m 0.5 --rear-target-speed-kph 3.35 --rear-min-pit-speed-kph 3 --measurement-noise --noise-seed 20261004 --support-allocation active --support-allocation-gains evidence/static_fr_ii/support_allocation_gains_20261003.json
```

使用 `monitor` 只求解/记录、不施加附加力；`off`（默认）保留基线。不要同时传 `--contact-gain-bundle`，那是另一项旧反馈增益替换试验。

恢复复核：将入口替换为 `scripts/run_rear_recovery_trial.py`，增加 `--abort-phase RR_HOLD`、使用另一输出目录，其余参数相同。诊断入口只允许坑前 PRELOAD/HOLD 注入。正常任务结果应 FAIL，`recovery_report.json` 应恢复 PASS。

`scripts/export_support_allocation_evidence.py` 从本地 runs 导出对照、修正峰值、实际力快照交接和恢复报告；结果存于 `evidence/static_fr_ii/support_allocation_validation_20261004.json`，完整 runs 不入 Git。IO 通道不变；日志保存实际最终施加 Fact 及分配状态、参考、修正和耗时。
