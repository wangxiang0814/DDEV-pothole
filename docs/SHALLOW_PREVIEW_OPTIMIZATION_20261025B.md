# 专家二预瞄与轮载优化第二轮（2026-10-25）

**本轮完成13项控制研究对照、3项独立接触模型对照和2项原候选回归。没有新增控制参数通过深坑联合筛查，尚不能交付“10cm深坑、1–6km/h鲁棒通过”的算法。** 保留用户已选MF52研究基线、原V2候选及专家一；没有扩大硬件能力、放松阈值或用降低目标速度拼出能力范围。所有原生运行40s，无姿态截断；没有导出视频。

失败映射前馈与爬沿转矩再分配已从活动代码清理，源码、参数和测试保留在[归档](../archive/preview_development_20261025b/README.md)。只保留默认关闭的快速轮载研究接口及明确来源的悬架几何。

## 本轮确认的问题

1. **下压力与时机需要协调，不能只增大前馈。** 保留V2在10cm宽坑前轮初次失载时，几何预瞄已达−100mm，整形参考仅约−16mm。映射前馈和提前时机可改善冲击，却会与车身反馈相互作用，并增加部分速度/滑移问题。完整运动比是分段变化的，不能用一个常数代表全部行程。
2. **轮载稳定不等于轮速稳定。** 快速轮载反馈下的最差事件发生在后右轮爬出坑沿：车身向前约0.269m/s，轮周速度约−3.768m/s，原生Kappa约−19.85；近似切平面修正后仍约−3.956m/s，不能全部按轮速代理定义误差解释。该事件附近2s内实际电机约91.1%的时间处于1000Nm/s变化率边界。见[事件数据](../evidence/shallow_mapped_force_20261025/contact_load05/event.json)与[曲线](../evidence/shallow_mapped_force_20261025/contact_load05/event.png)。
3. **预先分配爬沿转矩也存在代价。** 同侧请求总转矩守恒并不保证实际驱动总量守恒；轮速反馈、轮载变化及电机速率限制仍会改变执行结果。本轮再分配反而增加速度波动与轮载峰值，已排除。
4. **10cm还不能作为策略切换线。** 之前静态核查仍显示行程余量；当前先失败的是动态接触、轮载、滑移与倒溜。既不能凭行程估计宣称能过10cm，也不能凭这些失败证明悬架已经够不到。真实底盘实体与执行器实体规格仍不完备。

## 不依赖MF-Swift的接触对照

核查本机[官方Tire Models手册](F:/TruckSim2019/TruckSim2019.0_Prog/Help/Screens/Tire_Models.pdf)48–49页后，独立比较了原PAC52的单点与150mm纵向双点平均接触，另做半步长。双点方法平均两端路面高度、由高度差求有效坡度，**不是短障碍包络模型**。接触长度150mm为未标定研究假设。

原有接口禁止将这套内部接触参数与外部MF52混用，预检拒绝后保留该约束，未启动那项错误组合。之后3项真正执行的模型对照均显式标为MODEL_DIAGNOSTIC_ONLY，两个通过标志均false；它们属于原车型独立研究，不计入已采纳MF52控制器的能力。

## 后续优化顺序

先建立能处理短坑沿、无需现有MF-Swift授权的独立接触参考，分别检查静态轮载/力矩、平地低速滚动、入坑/重接地和步长收敛；与当前MF52、原车型并列，核验后再决定是否采用。不能以修改坑形或接触参数获得通过来替代核验。

接触基础可信后，继续采用预瞄前馈＋反馈：将轮载建立、重接地减力与车身升沉/侧倾/俯仰协调，再按实际转矩变化率提前建立爬沿需求，避免无法执行的高频PD切换。先过8–10cm的1–3km/h深坑锚点，再覆盖两类坑的1–6km/h及误差/时延；保持同一套冻结参数验证，失败时不宣称扩展能力。本轮不建议继续增加增益或启动大规模合格样本采集。

## 当前代码、回归与复现
