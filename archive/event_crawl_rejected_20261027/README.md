# 未采纳的逐轮接触平面导入原型

`contact_reference_prototype.zip`保留原始模块、测试和带诊断开关的worker；每个文件和ZIP的SHA256见`sha256.json`。它已经退出活动源码与CLI，不是可采用的模型。完整运行源码版本见`evidence/shallow_event_crawl_20261026/source_archive_index.json`，原生历史仍在各自runs目录。

原型试图对同一物理坑形计算刚性圆轮支撑高度和切平面，以每轮ZGND/DZDX/DZDY三项标量导入。两类10cm、1km/h接近速度、80秒诊断均失败；最大轮载分别达到约17.1/16.2倍静载，不能采纳。

官方VS_STI.pdf第19页说明导出的Xctc/Yctc/Zgnd来自第三方最终infVar，因此不能仅比较导入、导出高度判断接口正确。现有轨迹的完整平面残差仍达46–297mm。导入单位m及无量纲坡度得到echo确认；但原型用上一帧导出的接触点作为高度锚点，外胎道路回调实际可自行指定查询坐标，两者没有一致性保证。商业DelftTyreWrapper源码不提供，尚不能确认内部原因，也没有经过证明的符号或尺度修正。

不得把上述失败用来宣称所有控制失败均由轮胎模型造成。后续如重启该模型研究，需在实际道路回调请求点返回一致的高度和梯度，验证完整平面、静态力/力矩、滚动、重接地及步长收敛，再另行决定是否采用。不要把本ZIP零散文件复制回当前控制器。

## 逐轮爬沿转矩再分配对照

`rotation_reallocation_prototype.zip`及`rotation_sha256.json`保留另一条已退出活动代码的对照，复用此前归档的同侧可行零和投影，在新的阶段识别、降速任务及总爬沿补偿零滞后条件下单独核查。它把转矩向爬沿车轮转移，同侧总请求不变，但实际电机PD和变化率仍可改变该总和，不能称为实际总驱动力恒定。

10cm宽坑、3km/h接近、100秒，关闭对照的原始CSV与原crest基线逐字节相同。启用200Nm有界偏置后，RMS约0.758→0.855m/s²、轮速误差1.072→3.171m/s、倒溜0.104→0.176m，未改善联合指标。因此相关参数、分配函数、父控制器钩子和专属测试均已移出活动目录。历史配置与源码仍通过各run/source及源快照可恢复；只读新事件复核明确列出已退役且不参与验收计算的控制参数，不把旧配置重新当作当前可执行配置。

## 附着预算及反馈试验

`grip_budget_prototype.zip`保留附着分配系数0.65→0.85的失败对照。深宽坑轮速误差恶化至1.896m/s；原0.65已恢复。

`braking_hub_feedback_prototypes.zip`保留独立入坑制动分配与轮心运动补偿。前者在原模型和道路回调对照中均未联合通过；后者在匹配的圆轮道路回调宽坑10cm对照中RMS 0.560→0.637m/s²、倒溜0.113→0.179m、旧轮速代理0.606→0.676m/s。两项均移出活动接口，不能将轮速代理含几何运动这一事实直接变成放宽验收。历史配置仅用于原源码复现。
